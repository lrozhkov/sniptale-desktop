# ADR 0006: Cursor trajectory blocks

Status: Accepted, 2026-10-31, jointly agreed with the extension. The frozen shared fixture SHA-256 is dc308f3fa394bc44db5686e11c5fb697ef628be5be5a1a09cde174560f4c1294. Schema, canonical encoding, source-driven partition, greedy block packing, anchors, clock metadata, click relationships, and legacy fallback are fixed by this decision and that fixture. Production collector/storage/transport/editor integration and real VM acceptance remain pending; existing inline cursor evidence does not establish this contract.

## Responsibility and invariants

The user selected one `cursor-trajectory-v1` format and one `sed-window-v1` simplifier for browser and Desktop capture. There is no lifetime sample limit or repeated simplification of closed history. Available source observations define the accuracy reference; unknown movement between observations is not reconstructed as fact. Existing collection consent and keyboard policy remain in force.

`telemetry/**` owns event-clock conversion, active-time projection, frame coordinates, segmentation, semantic anchors, and the pure simplifier. `recording/**` owns the recording-to-trajectory binding and finalization. `transfer/**` owns protected append storage, integrity, paged reads, assignments, receipts, and authorized cleanup. `protocol/**` owns the platform-neutral DTOs and boundary validation. `app/**` coordinates bounded writer commands and current controller authorization. `ipc/**` retains control framing; attachment bytes must not traverse the resident control pipe.

Windows are source-driven, with at most 250000 active microseconds of input span and 512 working observations, including a carried anchor. Before adding an observation that would exceed the span, close the old window. Reaching 512 observations closes the window after that observation. There is no timer-driven flush of an active window; silence retains the bounded pending window until a source event or explicit lifecycle/gap command. The span bound is not a wall-clock flush-latency promise. A writer queue holds at most two pending blocks. A block contains at most 512 records and 65536 canonical plaintext bytes, including its header. Filling any working buffer does not authorize changing the error bound or rewriting earlier blocks. Writer backpressure and storage failure preserve committed blocks and video and explicitly reduce trajectory completeness.

## Deterministic simplification

Coordinates are integers in Q8 source-frame pixels: `floor(value * 256 + 0.5)`. Time is integer `activeTimeUs`; producers remove pauses once before simplification. Consumers keep these source times unchanged and map them to project/display time only during evaluation.

For endpoints A/B and interior observation P, let `dt = tB - tA`, `dp = tP - tA`, `nx = (xP - xA) * dt - (xB - xA) * dp`, and likewise `ny`. Split when `(nx² + ny²) * 10000 > (199 * 256)² * dt²`. Comparison is exact; TypeScript uses BigInt and Rust uses checked integer arithmetic. If arithmetic cannot establish that deletion is safe, retain every observation in that interval. Equal maximum errors select the smallest observationSeq. Use an explicit stack and emit retained observations in source order.

First/last observations and semantic anchors divide the window into independent intervals. Down/up/click, the last available predecessor and first subsequent move, both sides of visibility/observation changes, pause/resume, geometry changes, gaps, and recording start/stop are anchors. A lifecycle boundary does not invent a coordinate. Equal times with different positions close one segment and start another without shifting either timestamp. Identical ordinary moves may merge; semantic events may not.

Neighbor preservation is mandatory even when its before-button/after-button relationship becomes known after that observation was sealed as an endpoint. Explicit neighbor flags are added only while mutable and when the relationship is known. Consumers can infer adjacency from source order; nobody edits an immutable anchors array to add future knowledge.

The final observation of a closed window is the next window's retained starting anchor when its span to the next observation is at most 250000 microseconds. If that span is larger, the new observation starts the next window itself; the previously saved endpoint remains available to the evaluator without a larger working window or a synthetic boundary coordinate. A carried anchor is not appended twice with the same observationSeq. Closed windows and blocks remain immutable. Interpolation crosses neither segment boundaries nor gaps. Holding the final position is permitted only inside an explicitly declared continuing observed interval, never through an unknown interval.

## Proposed canonical byte encoding

The encoding identifier is `json-ascii-int-v1`. A block is a compact UTF-8 JSON object with no BOM, whitespace, newline, duplicate keys, insignificant numeric spellings, or trailing bytes. Object keys are sorted recursively by ascending ASCII byte order. Arrays retain their specified order. All keys, enum strings, identifiers, and hashes are ASCII; there is no free-form text. Numbers are base-10 integers from 0 through 9007199254740991, with no sign, exponent, fraction, or leading zero. Booleans and null use their JSON spelling. Every shape is closed and all listed keys are required; nullable fields are explicit null. Encoding a parsed value must reproduce its input bytes exactly.

Each block has `formatVersion: 1`, `recordingId`, `trajectoryId`, `sequence`, `startTimeUs`, `endTimeUs`, and `records`. recordingId uses the existing recording identifier grammar. trajectoryId is 32 lowercase random hexadecimal characters and is the immutable source identity. A separate private writer-generation token fences local append commands; restore preserves trajectoryId and canonical bytes while creating a fresh local writer generation. sequence starts at zero and is contiguous. startTimeUs/endTimeUs equal the minimum/maximum time covered by the records. A hash is exactly 64 lowercase hexadecimal characters. Geometry must match the recording's validated source-frame geometry; virtual desktop origins never enter an attachment.

Block packing is common production behavior, not a peer-specific choice. Append the next whole record to the maximal prefix that fits both limits, calculating canonical header bounds and sequence before checking bytes. If it does not fit, seal the current nonempty block, increment sequence, and test the same record in a fresh block. A single record that cannot fit fails with explicit incomplete status rather than retrying forever. After a boundary or gap record, immediately seal the nonempty block. Finalize seals the remainder. Window closure alone does not seal a block; no timer, wake-up cadence, or delivery state adds seals. These rules make block counts and stream digests reproducible from the same normalized records and lifecycle/gap commands.

`blockSha256 = SHA256(blockBytes)`. The canonical stream is the concatenation, in sequence order, of `u32LE(blockBytes.length)` followed by blockBytes. `streamSha256` is SHA-256 of that stream, including length prefixes; the empty stream uses SHA-256 of empty bytes. A manifest entry stores the prefix digest after its block so reconnect can validate a contiguous cursor without retaining the full stream in memory. Recovery may rehash the immutable prefix with bounded streaming reads.

## Proposed record shapes

Records are ordered by source/lifecycle order within each block and then by block sequence. Samples have globally increasing observationSeq, including across blocks. observationSeq belongs to the raw normalized input and is never renumbered after simplification. Segment IDs start at zero and increase; segment metadata precedes its first sample. A gap may account for missing source sequence values. Header and counter representability limits are format limits, not an operational history quota; exhaustion produces an explicit incomplete result.

- A segment record has `kind: "segment"`, `segmentId`, `activeTimeUs`, `width`, `height`, `clock`, and `reason`. width and height are positive u32 values; per-segment validation still requires the actual source-frame geometry and existing capture limits. reason is start, resume, visibility, observation, geometry, clock-discontinuity, zero-time-discontinuity, or after-gap. clock has `source`, `timestampQuantumUs`, `resolutionBoundUs`, and `mappingUncertaintyUs`; source is windows-message-time or dom-event-time. timestampQuantumUs is a positive integer or null when unknown; the other bounds are nonnegative integers or null when unknown. DOM precision cannot be inferred from one timestamp difference. Unknown values are explicit null, never a claim of microsecond accuracy. The clock mapping is immutable within a segment and a mapping discontinuity starts a new segment.
- A sample has `kind: "sample"`, `segmentId`, `observationSeq`, `activeTimeUs`, `xQ8`, `yQ8`, `visible`, `observed`, `event`, `button`, `relatedObservationSeq`, and `anchors`. event is move, down, up, or click; button is none, left, middle, right, x1, or x2. Coordinates are either both integers or both null. Observed coordinates satisfy `0 <= xQ8 < width * 256` and the corresponding height bound. observed false requires both coordinates null. relatedObservationSeq is null except that a raw click with a proven link to its corresponding up can reference that earlier observationSeq; unknown relationships stay null. anchors is an ASCII-sorted unique subset of start, stop, before-button, after-button, visibility, observation, pause, resume, geometry, gap, and discontinuity. Raw records retain source order, including equal timestamps; they are not sorted again by event kind. Visibility and observation changes require segmentation; neither a hidden nor an unavailable point is silently converted to position zero.
- A boundary has `kind: "boundary"`, `segmentId`, `activeTimeUs`, and `reason`, with reason pause, stop, visibility, observation, geometry, clock-discontinuity, or zero-time-discontinuity. It closes the segment. A following segment supplies the next observed interval. Pause and resume can have equal activeTimeUs and still remain separate boundaries.
- A gap has `kind: "gap"`, `segmentId`, `fromTimeUs`, `toTimeUs`, `firstLostObservationSeq`, `lastLostObservationSeq`, and `reason`. reason is input-overflow, writer-backpressure, source-unavailable, storage-failure, or clock-discontinuity. Lost sequence bounds are both known integers or both null. A gap closes the current segment. An unknown end stays null in immutable bytes; a later segment supplies its semantic end without rewriting it. No interpolation traverses an open gap. Header bounds use fromTimeUs and the known toTimeUs; a null end contributes only fromTimeUs to header bounds and remains semantically open. The final descriptor retains incomplete status even if capture subsequently recovers.

Windows low-level input supplies down/up; browser input can additionally supply a trusted click event. Preserve available source events independently and do not manufacture a second raw observation from the same OS event. Presentation emits one marker for a linked interaction: raw click takes precedence at its exact source time/position over the derived marker of its proven down/up pair. Without raw click, Desktop can derive a presentation marker at the up observation's time and position, without storing it as a source observation. An unpaired click remains independent. This change does not introduce new drag-classification thresholds. Lifecycle boundaries do not invent begin/end coordinates; neighboring observed anchors are retained when available.

## Descriptor, manifest, and negotiation

The descriptor has `format: "cursor-trajectory-v1"`, `formatVersion: 1`, `algorithm: "sed-window-v1"`, `encoding: "json-ascii-int-v1"`, `trajectoryId`, `state`, `finalized`, `totalBlocks`, `totalRecords`, `totalSamples`, `totalBytes`, and `streamSha256`. Counts and digests describe the committed contiguous prefix only. state is complete, incomplete, or unavailable. unavailable requires finalized true and means collection is finally unavailable, not merely pending delivery to one peer. An interrupted write cannot become complete by omission; recovery derives incomplete state from the unfinalized durable journal even when disk exhaustion prevented a final update. A finalized descriptor is immutable. The empty unavailable descriptor has zero counts and the empty stream digest. No descriptor with finalized false is ACKable, including incomplete descriptors.

The new capability is optional `cursor-trajectory-v1` in extension.hello. Desktop adds `capabilities.attachments: {"cursorTrajectoryFormats":["cursor-trajectory-v1"],"maxBlockBytes":65536,"maxBlockRecords":512,"maxChunkRawBytes":32768,"maxManifestEntries":32}` to app.hello only for a requesting peer. Both sides must advertise support before attachment messages are enabled. A requesting client talking to an older Desktop treats the missing server advertisement as unavailable. A legacy client receives compatible video metadata plus an explicit existing telemetry-warning carrier; it receives neither an unknown descriptor field nor a silently reduced inline cursor track.

The existing extension.hello capabilities field is an array; app.hello capabilities is an object. Keep both shapes. The requesting extension sends the following complete hello, using its real bounded identity/version values:

```json
{"type":"extension.hello","protocolVersion":2,"settingsSchemaVersion":1,"connectionIntent":"user-requested","extensionId":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","extensionVersion":"0.5.2","minAppVersion":"0.1.0","supportedProtocolVersions":[2],"supportedSettingsSchemaVersions":[1],"capabilities":["desktop-settings-v1","durable-media-ack-v1","cursor-trajectory-v1"]}
```

The legacy warning uses the existing snapshot fields: cursorTrack null; no pointer actionEvents; a static-frame signal with id native-static-0, startTime 0, endTime 0, point null, and data `{"source":"cursor-trajectory","code":"format-unavailable","severity":"warning"}`. Keep the validated frame viewport and any independent allowed non-pointer telemetry. warning is the existing Rust retained-warning severity and an allowed scalar value for the extension parser; extend only the exact Rust source/code allowlist for this new carrier. A missing delivery capability does not mutate or delete the complete private trajectory descriptor.

For negotiated peers, recording.stopped and persisted recording snapshots have a compact cursorTrajectory descriptor. Existing non-pointer telemetry may retain its existing contract; new pointer observations and button events live in trajectory blocks. An additional `app.recording.attachment.available` metadata notification carries recordingId, the video SHA-256, and the descriptor after reconnect when video has already been acknowledged. This prevents video ACK from making the remaining sidecar undiscoverable.

Manifest pages contain at most 32 entries. Each entry has sequence, startTimeUs, endTimeUs, recordCount, sampleCount, byteLength, blockSha256, and prefixSha256. The page has fromSequence and nextSequence; nextSequence is null only at the committed prefix end. The requester cannot choose a larger page. No stop, reopen, backup, or import path materializes the complete manifest or record list into one message.

## Proposed attachment messages

Every request has type, protocolVersion 2, controllerLeaseId, recordingId, trajectoryId, and requestId. requestId uses the existing bounded identifier grammar and is echoed. Every response carries the same recording/trajectory/request identity and current controller lease. Unknown fields, invalid byte/count/index relationships, and unsupported negotiated formats fail closed.

- `extension.recording.attachment.manifest.request` adds nextSequence and prefixSha256. The supplied prefix must match the durable manifest at that cursor; zero uses the empty prefix digest. `app.recording.attachment.manifest` returns descriptor, fromSequence, entries, and nextSequence.
- `extension.recording.attachment.chunk.request` adds sequence and chunkIndex. `app.recording.attachment.chunk` returns sequence, blockBytes, blockSha256, chunkIndex, chunkCount, chunkByteOffset, chunkRawBytes, chunkSha256, and base64. Chunks contain at most 32768 decoded bytes, so a block has one or two chunks. Sizes, offsets, hashes, canonical block bytes, and recording/trajectory identity are checked before durable publication. Identical duplicate chunks/blocks are idempotent; conflicting duplicates fail without replacement.
- `extension.recording.attachment.ack` adds receipt with version 1, durable true, format cursor-trajectory-v1, state, totalBlocks, totalRecords, totalSamples, totalBytes, and streamSha256. It is accepted only against the exact finalized descriptor. Its result acknowledges only trajectory persistence; the existing media receipt keeps its video-only meaning.

Current selected lease and the exact media assignment are required for discovery, pages, chunks, retries, and receipts. The transfer owner retains a trajectory ledger and assignment independently of video source metadata. Video ACK may release video, but cannot remove the sole trajectory copy or its assignment. Trajectory ACK may release the sidecar only after its own durable commit. Explicit privacy erasure first retires and joins the writer generation; a delayed append cannot recreate erased state. Before changing or removing the authenticated head, the private source directory persists an exact `erase.requested` tombstone; readers and discovery refuse that source even if a later head write or unlink fails. Startup retries only such persisted explicit erasures, and retains the directory identity so an old writer cannot recreate it. Restore creates a new local writer generation and cannot reactivate a retired append command. No timer or missing receipt authorizes sidecar deletion.

The protected writer commits block data before its index entry, keeps bounded per-block parsing and I/O, and rejects an occupied identity containing different bytes. Crash recovery distinguishes an immutable committed prefix from an orphan tail. The manifest index must support bounded pages and time lookup without loading all entries. Destination paths, raw clock epochs, OS handles, user text, URLs, targets, and labels do not enter these DTOs or logs.

## Shared proof before implementation

The [frozen shared vectors](../../../contracts/native/fixtures/cursor-trajectory-v1.json) contain 11 SED cases, four source-driven partition cases, five normalization cases, two block-packing cases, canonical byte/digest and negotiation/fallback examples, pause projection, and a compact hour generator. They include time-dependent SED versus perpendicular distance, Q8 threshold values 509/510, equal-error tie selection, large products within u32 geometry, button relationships, equal-time discontinuities, visibility/geometry/gaps, and immutable anchor behavior. Rust and TypeScript must retain the same observationSeq and anchors. Changing frozen bytes requires a jointly agreed version.

The extension independently reproduced the complete hour through its source-driven recorder, SED, canonical packer, and incremental hash: 360001 samples, 360003 records, 1155 blocks, and 75588979 payload bytes, with stream SHA-256 27f79ea802bc324c9632f33c54534f68fea9f5f78b49afd2981604480937b8fb. Its 34 focused tests also checked the fixture-file digest and per-block canonical/hash continuity. This is independent algorithm/encoding proof, not an implemented Native Messaging attachment or VM claim; Rust must reproduce it and both peers must complete integration proof.

A compact deterministic generator describes a one-hour adversarial trace rather than checking a giant JSON file into either repository. Both languages stream it through the real collector/writer/reader and an independent accuracy oracle. It must retain more than 4096 points, preserve earlier canonical bytes and hashes after continuation, and keep collector, two-block queue, transport assembly, manifest pages, and editor cache memory independent of total duration. Backpressure, storage failure, stale lease, wrong assignment, corruption, conflicting duplicates, cancel/delete/restore, late append, and reconnect prefix conflicts require negative proof.

Real Windows/browser transport evidence and visual fast drag, stop/start, click, and pause/resume checks at 1x and 4x remain required. Existing inline PNG/MP4 proof is retained as earlier-scope evidence. The independent sandbox-first UI goal follows completion of this main integration.

## Source clock constraints

Windows hook callbacks must copy each MSLLHOOKSTRUCT timestamp before returning. The adapter extends the wrapping event-clock value and maps it to the recording clock before draining; one drain timestamp cannot replace individual event times. The API exposes message timestamps and GetMessageTime uses elapsed milliseconds since boot. GetTickCount64 is a possible mapping reference but its documented system-timer granularity is commonly 10–16 ms, so converting units alone does not establish microsecond accuracy. Platform implementation must establish and report its actual conversion uncertainty, preserve equal timestamps, and mark discontinuities instead of fabricating order by shifting time.

The browser normalizer uses trusted coalesced observations when available and otherwise trusted pointer observations, without duplicating their parent event or using predicted observations. Neither producer introduces a fixed sampling frequency. Worker wake-up cadence is an I/O scheduling choice, not a license to resample or drop source observations.

Primary references: [Windows low-level mouse data](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-msllhookstruct), [GetMessageTime](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getmessagetime), [GetTickCount64 precision](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount64), [W3C coalesced pointer events](https://www.w3.org/TR/pointerevents3/#coalesced-events), and [SED trajectory simplification research](https://arxiv.org/abs/1801.05360). sed-window-v1 is the project algorithm above, not a claim to implement CISED.

The Native source currently maps Screen and Region positions against fixed desktop bounds. ActiveWindow does not provide window bounds for each original input timestamp, so it returns a finalized unavailable cursor descriptor and emits the existing format-unavailable warning. No source archive is created in this case. Recording-events retains accepted button facts and proven timing; frame points remain null. Cursor and click switches remain independent: click-only collection creates no trajectory source, and cursor-only collection retains allowed position observations without button semantics.
