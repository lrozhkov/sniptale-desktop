# ADR 0007: Lossless recording event blocks

Status: Accepted. Desktop and extension agreed the wire design and fixture SHA-256 ab6c98e72dee964de142a6b24d13d1e448a3f412cbd7543153f9cc562918ddc2. Agreement freezes the schema and original fixture bytes; runtime integration and every proof obligation below remain required before acceptance or capability advertisement. This decision does not change the accepted cursor format or frozen fixtures in [ADR 0006](0006-cursor-trajectory-blocks.md).

## Scope and ownership

`recording-events-v1` carries accepted sanitized actions, keyboard activity, delivered repeat cadence, signals, lifecycle boundaries, and explicit losses. `telemetry/**` owns normalization, bounded active aggregates, and privacy narrowing; `protocol/**` owns closed DTOs and parser admission; `transfer/**` owns protected immutable blocks, indexing, delivery assignment, and receipts; `recording/**` owns the recording binding; `app/**` coordinates bounded workers and current lease authorization. This format does not add native gallery, editor, account, or cloud behavior.

A producer must not delete an accepted event because of history length, visual density, click proximity, target similarity, or a presentation heuristic. Derived editor views may group events while the immutable source retains them. No producer may silently saturate a counter or replace an observed input time with Stop, blur, pause, or a drain time.

## Encoding and identity

The format is `recording-events-v1`, algorithm `lossless-v1`, encoding `json-utf8-v1`, and formatVersion 1. Each source has recordingId and a random 32-character lowercase hexadecimal eventStreamId. A separate private generation token fences local writers. Restore preserves source IDs, original block bytes, and digests while creating a fresh local generation.

Blocks contain formatVersion, recordingId, eventStreamId, sequence, startTimeUs, endTimeUs, and records. sequence starts at zero and is contiguous. A record has recordSeq, segmentId, activeTimeUs, and its closed family fields below. recordSeq starts at zero and is contiguous across committed records; source observation sequence, when known for a loss, is a separate domain. Records retain source/lifecycle emission order. activeTimeUs records the actual source or lifecycle fact that permits emission; it is never a fabricated keyboard observation. Delayed aggregates retain their original input interval separately in their payload.

recordSeq is emission order, not timestamp order. Delayed facts from independent producers may have decreasing activeTimeUs within an open segment; the producer preserves their original times and never sorts or rewrites sealed history. Block startTimeUs/endTimeUs are the minimum/maximum admitted envelope times, including a known gap end. Event time queries use the durable interval index rather than assuming chronological block ranges. Before pause, privacy transitions, or Stop closes a segment, a flush/join barrier admits every already accepted old-phase fact through the original source cutoff and flushes bounded aggregates. Old-phase facts are neither discarded at drain time nor reassigned to the new phase. A failed barrier is an explicit incomplete gap; it cannot certify a complete recording.

All times and durations in captured event DTOs are nonnegative safe integer microseconds with explicit Us suffixes. Their unit does not establish clock accuracy. Per-segment clock metadata follows ADR 0006. The editor creates its seconds-based projection after admission; seconds fields are not a second time authority in these blocks. Existing sanitized action/signal DTOs use this integer-time adaptation on the wire.

Every integer field, including Us/Seq/count/version/revision/header fields, IDs represented as numbers, clock integer metadata, and cadence ticks, uses the JSON lexical grammar 0 or [1-9][0-9]* and is at most 9007199254740991. Fractional syntax, exponent syntax, and negative zero are forbidden for those fields even if a language parser rounds the value to an integer. Admission checks the original number token before any floating-point conversion. Only finite point coordinates, scroll positions, and wheel deltas may use ordinary JSON floating-point syntax. This rule preserves original bytes and does not impose a common float serializer.

Point coordinates and scroll deltas may be finite JSON numbers. Points are normalized source-frame coordinates in [0,1]; unavailable points are null. A producer writes compact valid UTF-8 JSON. A consumer rejects a BOM, duplicate keys, nonfinite values, unknown fields, invalid numbers, and trailing JSON values. The encoding does not require cross-language float serialization or object-key order. Consumers hash, store, forward, back up, and restore the original bytes; they never parse and reserialize a block to establish its identity.

Use the block, queue, manifest-page, chunk, greedy packing, block digest, and length-prefixed stream digest bounds defined in ADR 0006. The event format has no duration or lifetime record quota. Block header time bounds cover record activeTimeUs plus a known gap end, not historical fields referenced by an update. A durable action/signal interval index supports time queries for delayed aggregates without loading the whole history. A closing boundary or gap seals the current block; an opening segment does not. Scheduling and delivery do not add seals.

## Closed record families

Every field listed for a family is required. Nullable fields use explicit null. No record contains an unbounded history array.

| Family | Additional fields and constraints |
| --- | --- |
| segment | clock and reason. reason is start, resume, visibility, privacy, clock-discontinuity, or after-gap. Segment IDs start at zero and increase. This record opens the segment. |
| boundary | reason is pause, stop, visibility, privacy, or clock-discontinuity. It closes the current segment. A confirmed Stop during Pause may finalize the already closed prefix without a fabricated Resume. |
| action | action, a closed sanitized action DTO with id, kind, timeUs, durationUs, point, label, data, and preset. kind is KEY, CLICK, SCROLL, or PAUSE; preset is NONE. keyboardRepeats, animation, DOM identity, sourceAnchor, and editable presentation fields are excluded. |
| action-update | actionId, revision, and data. The base action must precede the update. revision starts at one and increases for that action. Only the bounded completion fields below may change; the update never overwrites the base block. |
| signal | signal, a closed DTO with id, kind, startTimeUs, endTimeUs, point, and data. kind is typing, keyboard-hold, cursor-idle, or static-frame. Growing keyboardRhythm/keyboardRepeats arrays are excluded. Each typing fragment has its own id and explicit group/continuation identity. |
| keyboard-repeat-block | ownerKind (action or signal), ownerId, phase (onset or repeat), and cadence. The owner must precede the block. cadence has version 1, id, startTimeUs, quantumUs 1, count, encoding (delta-us or rle-us), and ticks. A cadence block represents at most 512 delivered observations. delta-us has one nonnegative delta per observation, starting at zero. rle-us has flattened [delta,run] pairs with positive runs whose sum equals count. There are at most 1024 tick integers. Decoding must reproduce each admitted normalized source time. |
| gap | source (keyboard, signal, or producer), fromTimeUs, toTimeUs, firstLostSourceSeq, lastLostSourceSeq, lostCount, and reason. Nullable lost bounds/count are explicit; known bounds must be ordered and consistent with the count. reason is input-overflow, writer-backpressure, storage-failure, source-unavailable, clock-discontinuity, unknown-record, oversize-record, or counter-overflow. A gap closes the segment and permanently makes the descriptor incomplete. |

KEY labels use a closed union of existing sanitized native and browser commands: unique standalone/chord modifiers Ctrl, Alt, Shift, and Meta; named ArrowUp, ArrowDown, ArrowLeft, ArrowRight, Home, End, PageUp, PageDown, Insert, Delete, Backspace, Enter, Escape, Tab, Space, F1 through F24, and the existing native Unknown placeholder, optionally with those modifiers. A single uppercase ASCII letter or digit is permitted only with Ctrl, Alt, or Meta. Shift+A, duplicate modifiers, F01/F25, punctuation, arbitrary text, and alternative arrow spellings are rejected; the browser maps presentation Up/Down/Left/Right to the corresponding Arrow names. Anonymous typing retains no character or key label. CLICK, SCROLL, and PAUSE labels are fixed Click, Scroll, and Pause. Action IDs, group IDs, cadence IDs, and references use the existing bounded identifier grammar. They identify source facts, never DOM targets.

KEY data has downTimeUs, upTimeUs, pressDurationUs, lastObservedTimeUs, repeatCount, completion, keyboardAttackId, keyboardOnsetTimeUs, groupId, continuationOf, ctrlKey, altKey, shiftKey, and metaKey. All are required; unknown times, modifier facts, and optional references are null. completion is observed, released, lost, or cancelled. lastObservedTimeUs is the last actual delivered input fact. pressDurationUs is known only with a proven down/up pair. repeatCount excludes the initial down and counts delivered repeats exactly. A missing keyup keeps upTimeUs and pressDurationUs null; Stop/blur cannot supply them. A KEY action-update data object has upTimeUs, pressDurationUs, lastObservedTimeUs, repeatCount, and completion. Update time may be a real lifecycle boundary while lastObservedTimeUs remains the older input time. A lost/cancelled completion cannot advance lastObservedTimeUs beyond admitted input/cadence evidence.

Onset and repeat phases require delivered source evidence. A native producer maintains bounded per-key transition state from actual down/up facts; a delivered repeat does not create another keyboard attack. A key already held when observation starts has no invented onset: unknown onset time and attack identity remain null, and missing source evidence is explicitly incomplete. Neither eventCount nor a guessed OS repeat rate can reconstruct cadence. Safe command observations pass the existing sanitize allowlist independently of anonymous typed-text activity.

CLICK data has button (integer 0 through 31), gestureId, gestureType, completion, downTimeUs, upTimeUs, pressDurationUs, lastObservedTimeUs, clickCount, semanticEndTimeUs, dragStartTimeUs, pointerCancelled, dropObserved, upPoint, ctrlKey, altKey, shiftKey, and metaKey. gestureType is click, hold, drag, selection, or native-drag when known; it is null otherwise. completion is observed, released, lost, cancelled, or semantic. clickCount is a positive safe integer. Every unknown relationship time, modifier, cancellation/drop fact, gestureId, and upPoint is null. A known upPoint is a proven normalized source-frame point, never a copied down point or a fabricated origin. semanticEndTimeUs and dragStartTimeUs require corresponding delivered semantic/drag evidence. CLICK action-update data has gestureType, completion, upTimeUs, pressDurationUs, lastObservedTimeUs, semanticEndTimeUs, dragStartTimeUs, pointerCancelled, dropObserved, upPoint, ctrlKey, altKey, shiftKey, and metaKey. The referenced action determines the update whitelist; immutable down identity/time/point do not change. Raw pointer trajectory records do not replace these accepted modifier, selection, drag, and completion facts.

SCROLL data has eventType (wheel or scroll), deltaX, deltaY, deltaZ, deltaMode, scrollX, scrollY, ctrlKey, altKey, shiftKey, and metaKey. Each field is required; an unobserved numeric or modifier fact is null. For wheel, deltas and deltaMode come from the actual trusted wheel event; deltaMode is 0, 1, or 2. For scroll, scrollX/scrollY are the actual observed scroll position and unknown wheel deltas remain null. A producer must not fabricate wheel deltas from a scroll position or discard an admitted deltaZ/modifier fact. PAUSE data has phase (pause or resume).

Typing signal data has eventCount, activity (keyboard or input), privacy (normal, protected, or unknown), groupId, and continuationOf. For normal input, eventCount is a positive safe integer and fragments close at the last real input or an admitted lifecycle boundary. A silent Stop does not extend endTimeUs. The producer emits another fragment/cadence block before a working aggregate reaches its bound. A representational limit emits an explicit counter-overflow gap or an exact continuation fragment; it never clamps a value.

The native field classifier is unavailable. privacy unknown preserves the existing anonymous aggregate policy: exact accepted eventCount and original first/last input boundaries, without characters, key identities, DOM/context, or new per-key anonymous cadence. Continuations preserve the exact total count, including across the former 65535 counter bound. unknown asserts neither a verified normal field nor a verified protected field. Browser normal cadence follows its existing recognized-protected-control checks. Known protected input follows the stricter coarse policy below.

Protected input preserves only coarse whole-second coverage: eventCount is null, point is null, startTimeUs and endTimeUs are multiples of 1000000, and there are no per-key cadence records or per-key owner identities. Counts are not accumulated into persisted fragments, including at a normal cadence-block boundary. The envelope activeTimeUs and privacy transitions use an independent public/lifecycle emission boundary or a coarse bucket, never a copied protected event timestamp. Coarse coverage may extend past the video's public final boundary; the editor clips only its derived view. IDs, recordSeq, gap bounds/counts, and fragment emission density must not encode the hidden input count or timing. A loss that may contain protected input uses null lost source bounds/count and coarse or public time bounds. Text, field values, targetId, DOM identity, selectors, targetTag, and targetType are forbidden in all event records.

Cursor-idle data has source (native-cursor or browser-cursor). Static-frame warning data has exactly source, code, and severity; severity is warning. The exact source/code pairs are listed below. A missing legacy provenance may be represented as source null only for source-unavailable; other unknown pairs are refused with an explicit incomplete prefix. No error text or arbitrary metadata is accepted.

| Warning source | Allowed codes |
| --- | --- |
| keyboard-hook or mouse-hook | events-dropped, drain-failed, signal-record-failed, event-record-failed, blocked, permission-denied, policy-denied, install-failed |
| cursor-telemetry | idle-signal-record-failed |
| cursor-trajectory | format-unavailable |
| recording-events | format-unavailable, input-overflow, writer-backpressure, storage-failure, source-unavailable, clock-discontinuity, unknown-record, oversize-record, counter-overflow |
| null | source-unavailable |

The unreleased v1 extension jointly accepted on 2026-11-01 preserves existing anonymous normal keyboard holds as immutable completed keyboard-hold signals. point is null and data has exactly privacy, downTimeUs, upTimeUs, pressDurationUs, lastObservedTimeUs, repeatCount, and completion. privacy is normal; protected and unknown are refused. completion is released, lost, or cancelled; observed and signal updates are excluded. All four time/duration fields are required nullable integers. repeatCount is a nonnegative safe integer. A known down equals startTimeUs; a known up or last observed input equals endTimeUs. A known duration requires both real endpoints and their exact nonnegative difference. Null facts remain unknown, including a released edge with an unknown timestamp. Unknown onset starts at the first actual observed repeat; silence or Stop never extends the input end. A later public envelope may carry the completed signal without changing those source bounds. Labels, characters, key identity, DOM data, group IDs, and continuation IDs are excluded. The [shared keyboard-hold vectors](../../../contracts/native/fixtures/recording-events-keyboard-hold-v1.json) are frozen at SHA-256 b76ae166fb09777a4b5a4efd504c8bfe53fad15540ca05305bf0589645f1b634; the main frozen fixture remains unchanged. Desktop supports receiving this shape but does not produce normal holds while its field classifier is unavailable.

A native safe-command observation with an unknown initial onset retains its actual repeat or release and null onset/attack/duration facts. One zero-width keyboard source-unavailable context gap marks that recording incomplete without claiming a lost input count. This context barrier preserves independently observed active command and button pairs; updates may reference an earlier matching base across segments. Later unknown initial keys do not add a gap per key. Actual queue or clock losses retain their separate loss barriers. Native anonymous unknown-field input retains the existing aggregate-only privacy policy and never becomes a normal hold or a fabricated Unknown KEY.

## Descriptor and delivery

The descriptor has format, formatVersion, algorithm, encoding, eventStreamId, state, finalized, totalBlocks, totalRecords, totalBytes, and streamSha256. Counts cover the authenticated committed prefix. state is complete, incomplete, or unavailable; unavailable requires finalized true. Empty unavailable has zero counts and the empty stream digest. A finalized descriptor is immutable. Crash recovery seals an unfinalized authenticated prefix as incomplete, even if Stop could not update its journal. No unfinalized descriptor is ACKable.

The capability token is recording-events-v1 in the existing extension.hello capabilities array. The independent app.hello field is capabilities.eventAttachments with recordingEventFormats and the shared block/page/chunk limits. It is omitted for a peer that does not request this capability. recording.stopped carries optional recordingEvents only after negotiation. A legacy peer receives an exact static-frame format-unavailable warning and no silently truncated event history. The warning source/code is recording-events / format-unavailable; this pair requires an exact retained-warning admission.

The separate message family is extension.recording.events.manifest.request, app.recording.events.manifest, extension.recording.events.chunk.request, app.recording.events.chunk, extension.recording.events.ack, and app.recording.events.available. Requests and solicited responses have protocolVersion 2, controllerLeaseId, recordingId, eventStreamId, and requestId. Manifest requests add nextSequence/prefixSha256; responses add descriptor/fromSequence/entries/nextSequence. Entries have sequence/startTimeUs/endTimeUs/recordCount/byteLength/blockSha256/prefixSha256. Chunk fields match the cursor attachment envelope. The events receipt has version 1, durable true, format, state, totalBlocks, totalRecords, totalBytes, and streamSha256. available is unsolicited, omits requestId, and adds videoSha256 and descriptor.

Every discovery, page, chunk, retry, and receipt requires the current selected lease and the exact media assignment. The video, cursor, and event receipts are independent. Video ACK cannot delete either sole history copy or its assignment. Assignment cleanup waits for video and every existing history stream to reach its own authorized terminal state. A read grant contains only bounded authorization metadata; attachment bytes never traverse the resident pipe. Privacy erase retires and joins the writer generation before deletion, and late commands cannot recreate erased state.

## Proof before acceptance

The [frozen fixture](../../../contracts/native/fixtures/recording-events-v1.json) covers all record families, exact original-byte integrity, event/signal history beyond old Desktop thresholds, repeat continuation, protected input, missing keyup, Stop after silence, pause/resume, gap persistence, boundary/size limits, conflicting duplicates, storage refusal, and generation fencing. Its compact generators require implementation by both owners; listing a case is not an executed runtime or VM result. Acceptance requires closed receiving guards, producer agreement, durable bounded storage, editor consumption, current lease/assignment negatives, and actual runtime/VM proof.

Native modifier facts use the accepted key-transition prefix and the original LLKHF_ALTDOWN context. Ctrl, Shift, and Meta remain null until source observations establish their state; a queue loss or rejected injected transition clears that certainty. Possible AltGr printable input remains anonymous activity, including an unknown initial Right Alt state. Named command keys remain eligible for safe labels. This avoids attributing a later modifier query to an earlier source timestamp; [Microsoft documents the callback timing](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc).
