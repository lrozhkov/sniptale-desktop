# Operate surfaces

Use this guidance for capture, recording, settings, and other task interfaces. The interface supports the task. Familiar behavior, clear values, and predictable control placement matter more than decoration.

## Hierarchy

Use one interface family. Keep labels readable and headings restrained. Use fixed semantic type roles. Preserve spacing and font choices from Sniptale web.

Keep parameter names secondary to current values. Use one primary command per task region. Keep ordinary commands neutral. Reserve accent color for declared active tools and selection.

## Components

Use consistent geometry, icons, labels, hover states, and focus rings. Do not invent an affordance when a familiar control meets the need. Keep theme and language selection compact.

Menus, fields, and dialogs retain their established commit timing. A checkbox changes a draft value. A switch changes an immediate setting. A failed save preserves the draft and provides recovery.

Toolbars use one Tab entry and arrow navigation. Moving focus does not activate a tool. A menu supports Escape, outside dismissal, item navigation, and focus return.

## Layout and motion

Adapt layout structurally. Do not shrink text to hide overflow. Use logical geometry and preserve reading order. Expanded text and RTL must keep essential actions reachable.

Overlays must escape clipping containers and remain within the viewport. Native menus and dialogs retain their own platform rules.

Use motion to explain state. Keep input immediate. Remove optional motion when the user requests reduced motion. Avoid decorative page entrances and idle animation.
